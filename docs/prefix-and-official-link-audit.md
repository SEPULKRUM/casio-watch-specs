# Supplied prefix and official Casio link audit

`node prefix_application_audit.mjs` checks all 1,371 supplied cases: current master segments, worldwide register observations, heritage mappings, 66 owner/community prefix readings, 79 guide examples and 70 scoped PDF prefix contexts. Full references incorrectly presented as prefixes are separated syntactically, with unknown letter meanings left unverified. In particular A159WEVJ-2JR is A / 159 / WEVJ / 2 / JR; 2 is a color code, not the series, and JR is a market suffix. Original supplied groupings remain in collapsed history and source records. Partial/unverified groupings, superseded records and historically scoped codes are deliberately distinguished from validated segmentations. This is not a claim that Casio publishes a universal acronym key.

The link survey fetched 32 official Casio sitemaps and made 5,854 availability checks of actual product/support URLs against model identity, final official host, HTTP status and specification content. Exact manufacturer product-name metadata can establish the page identity when a localized Japanese retail SKU differs from the canonical page reference. A regional SKU suffix alone does not create a new physical watch or supply specifications to another variant.

`research/official-casio-link-checks-2026-11-17.json` contains URL checks, response hashes, identity evidence and sitemap provenance only; full page HTML and source artwork are not published. The selected registry has 5,123 normalized model/reference groups: 2,935 product pages containing specifications and 2,188 support/service pages. Requests used only URLs already supplied or actually listed in Casio's own sitemaps. No model URL was guessed.

`python casio_links.py` generates `web/official-casio-links-data.mjs`. The shared resolver chooses the checked product page, then checked support/service page; otherwise it returns the explicitly labeled general Casio homepage. It validates the official host and complete model/reference identity again at runtime. Matching a module or family alone never selects another variant's page. The resolver is used in every search row, every model detail panel (including reference-only entries), and decoder results. It also covers future records automatically via the homepage fallback.

`node official_links_coverage.mjs` reconciles all watch identifiers and requires zero missing official destinations. Both report generators support `--check`. Registry generation supports `--check`. The browser and catalog build/tests remain required before publication. Page availability checks do not mark model facts or community interpretations independently verified.
